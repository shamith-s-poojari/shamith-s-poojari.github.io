Merkle Seal

Sep 2026

Seals a set of files under one Merkle root, then tells you which specific file changed rather than only that something did. Leaves and internal nodes are hashed with different prefixes, without which a crafted file could pose as an internal node. Odd nodes are promoted instead of duplicated, avoiding the flaw that let two different file sets share a root in early Bitcoin. Each file carries an inclusion proof, so verifying one file costs a handful of hashes instead of rehashing the set. It runs entirely in the browser, so nothing is uploaded.

  • SHA-256
  • Merkle trees
  • JavaScript

Chain of Custody: Digital Forensic Locker

Final year project, in progress

My final year project, currently in development. Tamper-evident custody for digital evidence. Files are hashed with SHA-256 and stored on IPFS, and only the 46-byte content identifier is anchored to a Solidity contract, which keeps gas cost over 90% below writing payloads on chain. An append-only audit trail records every custody transfer, so reconstructing provenance is an indexed contract query returning in about three seconds instead of two hours of reading logs by hand.
